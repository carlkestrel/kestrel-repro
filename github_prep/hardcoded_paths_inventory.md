## Fix Details

### `scripts/orchestrator/task_executor.py` (line 30)

**Before:**
```python
"PATH": f"/home/carlkestrel/miniconda3/envs/t4/bin:{os.environ.get('PATH', '')}",
```

**After:**
```python
"PATH": f"{os.path.dirname(sys.executable)}:{os.environ.get('PATH', '')}",
```

**Rationale:** `sys.executable` is the absolute path to the currently running Python. Its parent directory is the `bin/` (or `Scripts/`) directory of the active conda environment — no hardcoded username or conda root needed.

If the caller still sets `--conda-env`, the class accepts it but it is no longer used for path resolution.

## Alternative Approaches Considered

1. **`shutil.which("python")`** — resolves `python` from `PATH`. Works but depends on `PATH` being set correctly before the call; `sys.executable` is more reliable.
2. **Environment variable `CONDA_PREFIX`** — conda sets this automatically. Could be used as `Path(os.environ["CONDA_PREFIX"]) / "bin" / "python"`, but this raises `KeyError` outside conda and requires a fallback. `sys.executable` has no such edge cases.
3. **`Path(sys.executable).parent.parent / "envs" / conda_env / "bin" / "python"`** — overly complex; the conda env name is unknown at the call site in `task_executor`/`verifier` since those are called from the already-active Python process.
