# /repro-acquire

Safely clone and pin candidate repositories for deep learning paper reproduction.

## Usage

```
/repro-acquire [repo=<repository-url>] [role=<primary|reference|tooling>]
```

If no arguments are provided, clones all candidates from `candidate_repositories.csv` with decision=clone.

## What This Command Does

### Step 1 — Verify Discovery Completed

Before cloning, verify that `/repro-discover` has been run and `candidate_repositories.csv` exists.

### Step 2 — Static Security Audit (Pre-Clone)

For each repository to be cloned, perform static analysis without executing anything:

1. **Read repository metadata** (API or web):
   - Repository description and README
   - License file
   - Languages used
   - Recent commit history

2. **Flag security concerns**:
   - [ ] `curl | bash` in README or scripts
   - [ ] Unknown binaries or compiled executables in repository
   - [ ] Privileged Docker containers (Dockerfile with `privileged: true`)
   - [ ] Root/sudo requirement in installation scripts
   - [ ] Obfuscated or minified code
   - [ ] Missing or non-standard license
   - [ ] External data downloads from unknown/untrusted sources
   - [ ] Post-install scripts that modify system files

3. **Document all findings** in `repro_audit/repository_security_audit.md`

If any CRITICAL security issues are found, stop and report them. Do not clone until user approves.

### Step 3 — Safe Cloning

Clone repositories into the correct directories:

```
paper-reproduction-workspace/
├── primary/                  # Paper-author official repo
│   └── <cloned repo>
├── references/               # Independent implementations
│   ├── <impl-a>/
│   └── <impl-b>/
├── tooling/                 # Tooling projects (optional)
│   └── <tool>/
├── experiments/             # Your own experiment output
└── repro_audit/            # Audit reports
```

Clone with:
```bash
git clone --depth 1 <url>  # Shallow clone for history cleanup
# Or full clone if history is needed
```

### Step 4 — Pin Exact Commit

For each cloned repository:

1. **Identify the target commit:**
   - Use the release tag if available (matches paper version)
   - Use the commit aligned with paper submission date
   - Document the choice in `sources.lock.yaml`

2. **Checkout the exact commit:**
   ```bash
   cd <repo>
   git checkout <commit-hash>
   git submodule update --init --recursive  # If submodules exist
   ```

3. **Record submodule information** (if any)

### Step 5 — Record Sources

Generate `sources.lock.yaml`:

```yaml
# Generated by dl-paper-repro plugin
# Do not manually edit — regenerate with /repro-acquire

sources:
  primary:
    url: https://github.com/author/official
    commit: abcdef1234
    branch: main
    tag: v1.0
    license: MIT
    role: primary
    cloned_at: "2024-03-15T10:00:00Z"
    security_audit: "passed"

  references:
    - url: https://github.com/other/impl-a
      commit: 123456abcd
      branch: main
      license: Apache-2.0
      role: reference
      cloned_at: "2024-03-15T10:05:00Z"
      security_audit: "passed"

  tooling:
    - url: https://github.com/facebookresearch/hydra
      commit: fedcba9876
      tag: v1.3
      license: MIT
      role: tooling
      cloned_at: "2024-03-15T10:10:00Z"
      optional: true
      security_audit: "passed"
```

### Step 6 — Git LFS Check

If the repository uses Git LFS:

```bash
git lfs ls-files  # List LFS-tracked files
```

Record LFS requirements in `sources.lock.yaml` and ensure LFS is installed before proceeding.

### Step 7 — Verify Clone Integrity

After cloning:

1. [ ] Git working tree is clean (or expected state)
2. [ ] Submodules are initialized (if applicable)
3. [ ] Required files are present (model, dataset, training scripts)
4. [ ] No unexpected files or directories
5. [ ] README can be read

## What This Command Does NOT Do

- Does NOT run any installation scripts (setup.py, install.sh, Docker build)
- Does NOT execute `curl | bash` or any privileged commands
- Does NOT merge or rewrite Git histories
- Does NOT modify the cloned repositories
- Does NOT install dependencies or create environments

## Security Rules

1. **Never clone a repository flagged as CRITICAL security risk.**
2. **Never execute installation scripts during acquisition.**
3. **Never run Docker with privileged mode.**
4. **Never provide root/sudo credentials to any script.**
5. **Always perform static analysis before cloning.**
