Architecture Overview

dl-paper-repro uses a three-layer architecture:

Core Components

CLI Layer

reproctl.py is the single entry point that dispatches to:

  • Startup CLI (startup/cli.py): start, doctor, status, resume, stop, verify, version

StateStore (SQLite)

The orchestrator uses SQLite with WAL mode for persistent state:

Database Schema

-- Database: .repro/execution/state.sqlite3
-- Mode: WAL (Write-Ahead Logging)

-- metadata: key-value control state
CREATE TABLE metadata (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
-- Keys: control_state, plan_id, plan_path, mode, automation, mandatory_task_ids, budgets

-- tasks: task definitions and state
CREATE TABLE tasks (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  gate TEXT NOT NULL,
  deps_json TEXT NOT NULL,
  command TEXT NOT NULL,
  timeout_min REAL NOT NULL,
  acceptance_json TEXT NOT NULL,
  retry_json TEXT NOT NULL,
  task_json TEXT NOT NULL,
  status TEXT NOT NULL,
  attempts INTEGER DEFAULT 0,
  pid INTEGER,
  log_path TEXT,
  started_at TEXT,
  finished_at TEXT,
  retry_at REAL,
  failure_reason TEXT,
  updated_at TEXT NOT NULL
);

-- approvals: human approval workflow
CREATE TABLE approvals (
  approval_id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL,
  status TEXT NOT NULL,
  reason TEXT,
  created_at TEXT NOT NULL,
  expires_at REAL,
  decided_at TEXT
);

-- events: event journal
CREATE TABLE events (
  seq INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp TEXT NOT NULL,
  event_type TEXT NOT NULL,
  task_id TEXT,
  payload_json TEXT NOT NULL
);

-- heartbeats: process heartbeats
CREATE TABLE heartbeats (
  owner TEXT PRIMARY KEY,
  pid INTEGER NOT NULL,
  timestamp REAL NOT NULL,
  detail_json TEXT NOT NULL
);

Daemon Mode

# Start daemon
python scripts/reproctl.py orchestrator daemon --project . start --plan output/PAPER_PLAN.md

# Check status
python scripts/reproctl.py orchestrator daemon --project . status

# Stop daemon
python scripts/reproctl.py orchestrator daemon --project . stop

Policy Files

Create a policy file to control task approval:

{
  "policy_id": "custom-policy",
  "rules": [
    {"condition": "task.gate == 'gate_0'", "action": "auto_approve"},
    {"condition": "task.timeout_min > 60", "action": "require_approval"}
  ],
  "defaults": {
    "approval_required": false,
    "retry_on_failure": true,
    "max_retries": 3
  }
}
# Use policy
python scripts/reproctl.py orchestrator run --project . --plan output/PAPER_PLAN.md --policy policy.json

Approval Workflow

# View pending approvals
python scripts/reproctl.py orchestrator status --project .

# Approve
python scripts/reproctl.py orchestrator approve --project . apr_xxxxx

# Reject
python scripts/reproctl.py orchestrator reject --project . apr_xxxxx --reason "reason"

Run Strategies

# Until blocked or complete
python scripts/reproctl.py orchestrator run --project . --plan output/PAPER_PLAN.md --until blocked-or-complete

# Until complete
python scripts/reproctl.py orchestrator run --project . --plan output/PAPER_PLAN.md --until complete

# Run indefinitely
python scripts/reproctl.py orchestrator run --project . --plan output/PAPER_PLAN.md

Backup & Recovery

Backup & Recovery

State snapshots, migration, and disaster recovery

Backup

# Create backup
python scripts/reproctl.py orchestrator backup --project . --include-checkpoints --output-dir /path/to/backup

Backups include: state.sqlite3, startup directory, experiment tracker, and optionally checkpoints.

Restore

# List backups
ls /path/to/backup/

# Restore from snapshot
python scripts/reproctl.py orchestrator restore --project . --snapshot SNAPSHOT_ID

Migration

# Check migration
python scripts/reproctl.py orchestrator migrate --project . --check-only

# Execute migration
python scripts/reproctl.py orchestrator migrate --project . --target-version 2.0

Storage Governance

# Check disk space
python scripts/reproctl.py storage status --project .

# Plan cleanup
python scripts/reproctl.py storage plan-cleanup --project .

# Execute cleanup
python scripts/reproctl.py storage cleanup --project . --approved-plan cleanup.json

Lock Issues

EXIT_ALREADY_RUNNING (code 4):

# Check lock
cat .repro/run.lock
ps aux | grep <PID>

# Stop old instance
python scripts/reproctl.py stop --project .

# Or manually remove
rm .repro/run.lock

SQLite Locked

# Remove WAL files
rm .repro/execution/state.sqlite3-wal
rm .repro/execution/state.sqlite3-shm

# Restart
python scripts/reproctl.py orchestrator stop --project .
python scripts/reproctl.py orchestrator daemon --project . start --plan output/PAPER_PLAN.md

Reporting Bugs

Collect this information:

# Version
python scripts/reproctl.py version

# Doctor report
python scripts/reproctl.py doctor --project . > doctor.txt 2>&1

# Status
python scripts/reproctl.py orchestrator status --project . > status.json 2>&1

# Events
python scripts/reproctl.py orchestrator events --project . > events.json 2>&1

FAQ

Frequently Asked Questions

Common questions about dl-paper-repro

General

What is dl-paper-repro?

dl-paper-repro is a Cursor plugin and CLI system for evidence-driven reproduction of deep learning papers. It provides staged gates, GitHub repository discovery, hardware-fit auditing, and machine-readable evidence chains.

What is the CLI entry point?

python scripts/reproctl.py

What are the system requirements?

Python 3.8+, PyTorch, CUDA 11.0+ (for GPU), 8GB+ VRAM recommended. See Installation for details.

Startup vs Orchestrator

Startup manages project initialization, preflight checks, and lock management. It's lightweight and fast.

Orchestrator handles task scheduling, execution, and monitoring of long-running jobs. It persists state in SQLite and supports complex workflows.

Use Startup for quick checks and project bootstrapping. Use Orchestrator for training loops and multi-step pipelines.

strict vs optimized Mode

Aspectstrictoptimized
OptimizationsNoneAMP, DDP
Gate 3 RequiredNoYes
PerformanceSlowFast
Tolerance±0.5pp±0.5pp

Use strict mode for exact paper reproduction. Use optimized mode after passing the parity test (Gate 3).

Gate System

The six gates ensure quality at each stage:

  1. gate_0_paper_audit - Verify paper data and claims
  2. gate_1_preflight - Environment and dependencies
  3. gate_2_short_loop - L0-L3 validation tests
  4. gate_3_parity - Optimization parity check (required for optimized mode)
  5. gate_4_full_training - Complete training run
  6. gate_5_evidence - Final evidence verification

L0-L3 Short Loop Tests

These tests validate the pipeline before full training:

  • L0 (Smoke Test) - Single batch forward + backward pass
  • L1 (Overfit Test) - Memorize single batch
  • L2 (Mini-Loop Test) - End-to-end on small dataset
  • L3 (Checkpoint Resume Test) - Verify checkpoint save/load

Automation Modes

  • safe-auto (default) - Pauses for approval on critical decisions
  • manual - All tasks require approval
  • unattended - No waiting, auto-timeout on approval

Storage and Backup

Backups are stored in .repro/backup/ by default. Use --output-dir to specify custom location.

Clean up with storage plan-cleanup to see what can be removed, then storage cleanup to execute.

Glossary

Glossary

Terms and definitions used in dl-paper-repro

A

AMP (Automatic Mixed Precision)

Training technique that automatically switches between fp16 and fp32 to improve speed and reduce memory usage. Enable with --amp flag.

API (Application Programming Interface)

The CLI and Python functions provided by dl-paper-repro for programmatic access.

B

Backup

Snapshot of state.sqlite3, startup directory, and experiment tracker. Created with orchestrator backup.

C

CLI (Command Line Interface)

The reproctl.py script and its subcommands.

Controller

Core orchestrator component that manages the task execution loop.

CUDA

NVIDIA's parallel computing platform and programming model. Required for GPU training.

Cursor Commands

Slash commands available in Cursor IDE, defined in commands/*.md.

D

DDP (Distributed Data Parallel)

Multi-GPU training that distributes batches across GPUs. Use with torchrun --nproc_per_node=N.

Doctor

Preflight system that runs environment checks. Use doctor --project . to run.

E

Evidence Chain

Complete record proving reproduction results are traceable and reproducible.

G

Gate

Staged checkpoint that must pass before proceeding. Gates 0-5 cover paper audit through evidence verification.

GPU

Graphics Processing Unit, the primary hardware for deep learning training.

H

Heartbeat

Regular signal sent by the controller to indicate it's alive. Stored in controller.heartbeat.

L

L0-L3

Short loop test levels:

  • L0 - Smoke test (single batch forward + backward)
  • L1 - Overfit test (memorize single batch)
  • L2 - Mini-loop test (end-to-end on small data)
  • L3 - Checkpoint resume test

Lock

Mechanism preventing concurrent access. Stored in .repro/run.lock.

M

Mode

Execution configuration: strict (exact reproduction), optimized (with AMP/DDP), diagnose (debug), test, extend.

O

Orchestrator

Task scheduling and execution control subsystem. Commands: run, pause, continue, stop, status, events.

OOM (Out Of Memory)

Error when GPU memory is exhausted. Solutions: reduce batch size, enable AMP, use gradient checkpointing.

P

Parity

Verification that optimized mode produces equivalent results to strict mode. Required for Gate 3.

PID (Process ID)

Unique identifier for a running process. Used in lock files to track running instances.

Plan

PAPER_PLAN.md file defining tasks and dependencies for a reproduction project.

Policy

Rules controlling task execution and approval. Defined in JSON policy files.

S

safe-auto

Default automation strategy that pauses for human approval on critical decisions.

Schema

JSON structure definition. dl-paper-repro uses schemas for config, plan, task, and other files.

Secrets

Credentials and API keys that should be protected. Automatically redacted in logs.

Startup

Subsystem managing project initialization, preflight, and lock management.

StateStore

SQLite database storing orchestrator state with WAL mode. Located at .repro/execution/state.sqlite3.

T

Task

Minimum unit of work defined in a plan. Has command, timeout, acceptance tests, and retry policy.

Tolerance

Allowed deviation in metrics. Both strict and optimized modes allow ±0.5 percentage points.

W

WAL (Write-Ahead Logging)

SQLite journal mode that improves concurrent read performance. WAL files: state.sqlite3-wal, state.sqlite3-shm.

Watchdog

Component monitoring task timeout and exceptions. Triggers FAIL if task exceeds timeout.

Plugin Installation

The Cursor plugin is installed by placing it in your Cursor plugins directory:

# Clone or copy the plugin to your local plugins directory
git clone https://github.com/research-automation/dl-paper-repro.git \
  ~/.cursor/plugins/local/dl-paper-repro

# Verify the plugin is recognized
ls ~/.cursor/plugins/local/dl-paper-repro/

After placing the plugin, restart Cursor to load it. The plugin will appear in your Cursor settings under "Local Plugins".

CLI Setup

You can use the CLI directly with Python or install it as a package:

# Option 1: Use directly with Python
python ~/.cursor/plugins/local/dl-paper-repro/scripts/reproctl.py --help

# Option 2: Install in editable mode
cd ~/.cursor/plugins/local/dl-paper-repro
pip install -e .

# Now use from anywhere
reproctl --help

Verification

Verify the installation by checking the version and running a doctor check:

# Check version
python scripts/reproctl.py version

# Expected output:
# {
#   "reproctl": "0.2.0",
#   "plugin": "0.2.0",
#   "plugin_root": "/path/to/plugin",
#   "platform": "linux"
# }

# Run doctor to verify environment
python scripts/reproctl.py doctor --project .

GPU Setup

For GPU training, ensure CUDA is properly installed:

# Verify CUDA is available
python -c "import torch; print(f'CUDA available: {torch.cuda.is_available()}')"
python -c "import torch; print(f'CUDA version: {torch.version.cuda}')"

# Check nvidia-smi
nvidia-smi

You can run with REPRO_FAKE_GPU=0 to skip GPU checks during development or testing.

New Project

New Project Workflow

Step-by-step guide to starting a new reproduction project

Initialize Project

# Create project directory
mkdir my-paper-repro && cd my-paper-repro
git init

# Initialize reproctl
python scripts/reproctl.py init --paper https://arxiv.org/abs/xxxx.xxxxx --target "Table 3, mIoU"

This creates .repro/, experiments/, and initial state files.

Discover Repositories

Use the Cursor command /repro-discover or the CLI:

# Search GitHub for repositories
python scripts/research_crawler.py --query "semantic segmentation pytorch" --max-results 50

Evaluates repositories by: official status, stars, training scripts, README presence, license, and last commit.

Run Doctor

python scripts/reproctl.py doctor --project .
python scripts/reproctl.py doctor --project . --expected-cuda 12.0

Checks: Python, dependencies, GPU/CUDA, disk space, security, git status, plan existence.

Create Plan

Create output/PAPER_PLAN.md with:

  • Paper metadata
  • Task list with dependencies
  • Gate requirements
  • Budget constraints

Start Project

python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --mode strict

Checklist

  • Project initialized
  • Doctor checks passed
  • Plan created and validated
  • Project started

Optimization Techniques

AMP (Automatic Mixed Precision)

python scripts/reproctl.py launch --mode optimized_repro_safe --amp --epochs 300

DDP (Distributed Data Parallel)

# Single node, multi-GPU
torchrun --nproc_per_node=2 train.py

# Multi-node
torchrun --nnodes=2 --nproc_per_node=2 --master_addr=$ADDR train.py

Gradient Checkpointing

Reduces memory by recomputing activations during backward pass.

Monitoring

# GPU utilization
nvidia-smi dmon -s u

# Training monitor
python scripts/training_monitor.py --interval 5

# Check logs
tail -f .repro/execution/tasks/*/train.log

Out of Memory Solutions

  • Reduce batch size
  • Reduce image resolution
  • Enable AMP
  • Enable gradient checkpointing
  • Use smaller model variant

Quick Start

Quick Start Guide

Get up and running with dl-paper-repro in 5 minutes

Command Workflow

The typical project lifecycle follows this sequence:

1
python scripts/reproctl.py doctor --project .

Run preflight checks to verify environment

2
python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --mode strict

Bootstrap and start the project

3
python scripts/reproctl.py orchestrator run --project . --plan output/PAPER_PLAN.md

Run the task orchestrator

4
python scripts/reproctl.py orchestrator status --project .

Monitor project status

5
python scripts/reproctl.py orchestrator pause --project .

Pause execution if needed

6
python scripts/reproctl.py orchestrator continue --project .

Resume execution

7
python scripts/reproctl.py stop --project .

Stop gracefully when done

8
python scripts/reproctl.py verify --project .

Verify the evidence chain

Command Examples

Doctor Check

# Run preflight checks
python scripts/reproctl.py doctor --project .

# Specify expected CUDA version
python scripts/reproctl.py doctor --project . --expected-cuda 12.0

# Expected output:
# {
#   "checks": [...],
#   "summary": "PASS",
#   "exit_code": 0
# }

Start Project

# Start in strict mode
python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --mode strict

# Dry run (no lock acquired)
python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --dry-run

# Start in optimized mode
python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --mode optimized

Check Status

# Startup status
python scripts/reproctl.py status --project .

# Orchestrator status
python scripts/reproctl.py orchestrator status --project .

# Expected output:
# {
#   "project_root": "/path/to/project",
#   "control_state": "RUNNING",
#   "counts": {"PASS": 5, "RUNNING": 1, "PENDING": 3},
#   "tasks": [...],
#   "pending_approvals": [...]
# }

Resume

# Resume interrupted project
python scripts/reproctl.py resume --project .

Stop

# Graceful stop
python scripts/reproctl.py stop --project .

Verify

# Verify evidence chain
python scripts/reproctl.py verify --project .

Reproduction Protocol

Reproduction Protocol

Evidence-driven paper reproduction workflow

Protocol Overview

The reproduction protocol ensures rigorous, auditable paper reproduction through six staged gates.

Gate System

0
Paper Audit - Verify paper data and claims
1
Preflight - Environment and dependencies check
2
Short Loop - L0-L3 validation tests
3
Parity - Optimization parity check (for optimized mode)
4
Full Training - Complete training run
5
Evidence - Final evidence verification

Short Loop Tests (Gate 2)

L0 - Smoke Test

Single batch forward + backward pass. Verifies basic functionality.

L1 - Overfit Test

Memorize single batch. Verifies model can learn.

L2 - Mini-Loop Test

End-to-end on small dataset. Verifies full pipeline.

L3 - Checkpoint Resume Test

Verify checkpoint save/load produces identical results.

# Run all tests
python scripts/reproctl.py run-short-loop --level all

# Run specific level
python scripts/reproctl.py run-short-loop --level L0

Evidence Chain

Every operation generates traceable evidence:

  • Command logs with timestamps
  • Checkpoint artifacts
  • Metrics with provenance
  • Decision log entries

PatternReplaced With
Bearer <token>Bearer [REDACTED]
password=*password=[REDACTED]
token=*token=[REDACTED]
Authorization:Authorization: [REDACTED]
AWS_SECRET*[REDACTED]
OPENAI_API_KEY*[REDACTED]

Credential Management

Never hardcode credentials

Use environment variables and ensure .repro/ is in .gitignore.

# Set via environment
export GITHUB_TOKEN=ghp_xxxxx

# Use in config
# repro.yaml
github:
  token: ${GITHUB_TOKEN}

File Permissions

# Set permissions
chmod 600 .repro/run.lock
chmod 600 .repro/execution/state.sqlite3
chmod 700 .repro/

5 Principles

The system enforces 5 core principles:

  1. require_official_first - Paper author repo first
  2. require_strict_mode - Default to strict_repro
  3. require_raw_metrics - Metrics traceable to files
  4. require_provenance - Commit SHA required
  5. require_reproducibility - Results match within tolerance

Takeover Project

Takeover Workflow

Resume or continue an interrupted project

Assess State

# Check project status
python scripts/reproctl.py status --project .

# Check doctor report
cat .repro/startup/doctor_report.json

# Check orchestrator status
python scripts/reproctl.py orchestrator status --project .

# View recent events
python scripts/reproctl.py orchestrator events --project . --limit 50

Cleanup

# Stop old instances
python scripts/reproctl.py stop --project .
python scripts/reproctl.py orchestrator daemon --project . stop

# Remove stale locks if PID no longer exists
cat .repro/run.lock
rm .repro/run.lock

Resume

# Resume interrupted project
python scripts/reproctl.py resume --project .

# Or start orchestrator with resume flag
python scripts/reproctl.py orchestrator daemon --project . start --plan output/PAPER_PLAN.md --resume

Monitor

# Monitor status
python scripts/reproctl.py orchestrator status --project .

# View live events
python scripts/reproctl.py orchestrator events --project . --limit 10

Troubleshooting

Troubleshooting Guide

Fix common issues with diagnosis by symptom

Doctor Check Failures

Run doctor to identify environment issues:

python scripts/reproctl.py doctor --project .
cat .repro/startup/doctor_report.json

Common Failures

CheckCauseFix
cuda_matchCUDA version mismatchInstall correct CUDA or use --expected-cuda
disk_spaceNot enough free spaceFree up disk space
securitySecrets detected in filesRemove sensitive information
leftover_procsOld processes still runningStop old instances

Lock Conflicts

EXIT_ALREADY_RUNNING: 4

Another instance is already running or a stale lock exists.

# Check lock contents
cat .repro/run.lock

# Check if PID exists
ps aux | grep 

# Stop old instance
python scripts/reproctl.py stop --project .

# Or manually remove lock
rm .repro/run.lock

Recovery Failures

EXIT_RESUME_FAILED: 8

Could not recover from interrupted state.

# Check execution state
cat .repro/execution/execution_state.json

# Reinitialize with dry-run
python scripts/reproctl.py start --project . --plan output/PAPER_PLAN.md --dry-run

SQLite Database Locked

The SQLite database is locked by another process:

# Check WAL files
ls -la .repro/execution/state.sqlite3*

# Remove WAL to release lock
rm .repro/execution/state.sqlite3-wal
rm .repro/execution/state.sqlite3-shm

# Restart orchestrator
python scripts/reproctl.py orchestrator stop --project .
python scripts/reproctl.py orchestrator daemon --project . start --plan output/PAPER_PLAN.md

GPU Issues

# Check CUDA
python -c "import torch; print(torch.cuda.is_available())"
python -c "import torch; print(torch.version.cuda)"

# Check driver
nvidia-smi

# Skip GPU check (for testing)
REPRO_FAKE_GPU=0 python scripts/reproctl.py doctor --project .

Approval Workflow Stuck

Tasks stuck in WAITING_APPROVAL state:

# Check pending approvals
python scripts/reproctl.py orchestrator status --project .

# Approve task
python scripts/reproctl.py orchestrator approve --project . apr_xxxxx

# Or reject
python scripts/reproctl.py orchestrator reject --project . apr_xxxxx --reason "reason"

Diagnostic Commands

# 1. Environment
python scripts/reproctl.py doctor --project .

# 2. Project status
python scripts/reproctl.py status --project .
python scripts/reproctl.py orchestrator status --project .

# 3. Events
python scripts/reproctl.py orchestrator events --project . --limit 50

# 4. Logs
cat .repro/startup/startup.log
cat .repro/execution/daemon.log

# 5. Integrity
python scripts/reproctl.py orchestrator integrity-check --project .
python scripts/reproctl.py integrity-check
