Glossary

Terms and definitions used in dl-paper-repro

A

AMP (Automatic Mixed Precision)

Training technique that automatically switches between fp16 and fp32 to improve speed and reduce memory usage. Enable with --amp flag.

API (Application Programming Interface)

The CLI and Python functions provided by dl-paper-repro for programmatic access.

B

Backup

Snapshot of state.sqlite3, startup directory, and experiment tracker. Created with orchestrator backup.

C

CLI (Command Line Interface)

The reproctl.py script and its subcommands.

Controller

Core orchestrator component that manages the task execution loop.

CUDA

NVIDIA's parallel computing platform and programming model. Required for GPU training.

Cursor Commands

Slash commands available in Cursor IDE, defined in commands/*.md.

D

DDP (Distributed Data Parallel)

Multi-GPU training that distributes batches across GPUs. Use with torchrun --nproc_per_node=N.

Doctor

Preflight system that runs environment checks. Use doctor --project . to run.

E

Evidence Chain

Complete record proving reproduction results are traceable and reproducible.

G

Gate

Staged checkpoint that must pass before proceeding. Gates 0-5 cover paper audit through evidence verification.

GPU

Graphics Processing Unit, the primary hardware for deep learning training.

H

Heartbeat

Regular signal sent by the controller to indicate it's alive. Stored in controller.heartbeat.

L

L0-L3

Short loop test levels:

  • L0 - Smoke test (single batch forward + backward)
  • L1 - Overfit test (memorize single batch)
  • L2 - Mini-loop test (end-to-end on small data)
  • L3 - Checkpoint resume test

Lock

Mechanism preventing concurrent access. Stored in .repro/run.lock.

M

Mode

Execution configuration: strict (exact reproduction), optimized (with AMP/DDP), diagnose (debug), test, extend.

O

Orchestrator

Task scheduling and execution control subsystem. Commands: run, pause, continue, stop, status, events.

OOM (Out Of Memory)

Error when GPU memory is exhausted. Solutions: reduce batch size, enable AMP, use gradient checkpointing.

P

Parity

Verification that optimized mode produces equivalent results to strict mode. Required for Gate 3.

PID (Process ID)

Unique identifier for a running process. Used in lock files to track running instances.

Plan

PAPER_PLAN.md file defining tasks and dependencies for a reproduction project.

Policy

Rules controlling task execution and approval. Defined in JSON policy files.

S

safe-auto

Default automation strategy that pauses for human approval on critical decisions.

Schema

JSON structure definition. dl-paper-repro uses schemas for config, plan, task, and other files.

Secrets

Credentials and API keys that should be protected. Automatically redacted in logs.

Startup

Subsystem managing project initialization, preflight, and lock management.

StateStore

SQLite database storing orchestrator state with WAL mode. Located at .repro/execution/state.sqlite3.

T

Task

Minimum unit of work defined in a plan. Has command, timeout, acceptance tests, and retry policy.

Tolerance

Allowed deviation in metrics. Both strict and optimized modes allow ±0.5 percentage points.

W

WAL (Write-Ahead Logging)

SQLite journal mode that improves concurrent read performance. WAL files: state.sqlite3-wal, state.sqlite3-shm.

Watchdog

Component monitoring task timeout and exceptions. Triggers FAIL if task exceeds timeout.
