Frequently Asked Questions

Common questions about dl-paper-repro

General

What is dl-paper-repro?

dl-paper-repro is a Cursor plugin and CLI system for evidence-driven reproduction of deep learning papers. It provides staged gates, GitHub repository discovery, hardware-fit auditing, and machine-readable evidence chains.

What is the CLI entry point?

python scripts/reproctl.py

What are the system requirements?

Python 3.8+, PyTorch, CUDA 11.0+ (for GPU), 8GB+ VRAM recommended. See Installation for details.

Startup vs Orchestrator

Startup manages project initialization, preflight checks, and lock management. It's lightweight and fast.

Orchestrator handles task scheduling, execution, and monitoring of long-running jobs. It persists state in SQLite and supports complex workflows.

Use Startup for quick checks and project bootstrapping. Use Orchestrator for training loops and multi-step pipelines.

Use strict mode for exact paper reproduction. Use optimized mode after passing the parity test (Gate 3).

Gate System

The six gates ensure quality at each stage:

  1. gate_0_paper_audit - Verify paper data and claims
  2. gate_1_preflight - Environment and dependencies
  3. gate_2_short_loop - L0-L3 validation tests
  4. gate_3_parity - Optimization parity check (required for optimized mode)
  5. gate_4_full_training - Complete training run
  6. gate_5_evidence - Final evidence verification

L0-L3 Short Loop Tests

These tests validate the pipeline before full training:

  • L0 (Smoke Test) - Single batch forward + backward pass
  • L1 (Overfit Test) - Memorize single batch
  • L2 (Mini-Loop Test) - End-to-end on small dataset
  • L3 (Checkpoint Resume Test) - Verify checkpoint save/load

Automation Modes

  • safe-auto (default) - Pauses for approval on critical decisions
  • manual - All tasks require approval
  • unattended - No waiting, auto-timeout on approval

Storage and Backup

Backups are stored in .repro/backup/ by default. Use --output-dir to specify custom location.

Clean up with storage plan-cleanup to see what can be removed, then storage cleanup to execute.
